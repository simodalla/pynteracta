# pynteracta v0.2.0 — Posts read completeness (M15)

> **Status: PLANNED.** Spec for the next minor. Read-only, additive. No change to existing flows.
> Follows the conventions of the [foundation spec](v0.1-foundation.md) and the patterns logged in
> [`PROGRESS.md`](../PROGRESS.md) (M5 resource clients, M9 communities/catalogs). Index:
> [`ROADMAP.md`](../ROADMAP.md).

## 1. Objective

Complete the **read surface of the posts resource** by adding the seven posts `data/*` endpoints
present in the pinned swagger but not yet exposed. This rounds out post retrieval (by client UID,
capabilities, history, global feed, alternate community listing, visibility checks) before the
project moves on to attachments (0.3.0) and beyond.

Targets a **minor bump 0.1.0 → 0.2.0** via a `feat:` commit. Service-account and Google OAuth2
flows unchanged; all existing resource clients unchanged.

## 2. Endpoints in scope

All paths under `{base}/api/external/v2/communication/posts/`.

| # | Method | Path | Request DTO | Response DTO | Notes |
|---|---|---|---|---|---|
| 1 | GET | `data/post-detail-by-client-uid/{clientUid}` | – | `GetPostDetailResponseDTO` | Same shape as `post-detail-by-id`; keyed by client UID. Reuse the existing `Post` facade. Same `loadMainAttachment*` query flags as the by-id endpoint. |
| 2 | GET | `data/post-capabilities/{postId}` | – | `GetPostCapabilitiesResponseDTO` | Per-post capability flags. New facade `PostCapabilities`. |
| 3 | POST | `data/history-list/{postId}` | `ListPostHistoryEventsRequestDTO` | `ListPostHistoryEventsResponseDTO` | Post edit/event history. Paginated → `PageIterator`. New facade `PostHistoryEvent`. |
| 4 | POST | `data/global-stream` | – (filters via body/query — confirm at codegen) | `GlobalPostsStreamResponseDTO` | Cross-community home feed. Paginated → `PageIterator`. Reuse list-post element facade where possible. |
| 5 | POST | `data/community-list/{communityId}` | `ListCommunityPostsRequestDTO` | `PagedListPostsResponseDTO` | **Distinct** from the existing `list/community/{communityId}` (`ListCommunityPostsFilteredRequestDTO`). Lighter/unfiltered variant. Paginated → reuse `Post` list facade. |
| 6 | POST | `data/check-visibility` | `CheckVisibilityRequestDTO` | `CheckVisibilityWithCommentsResponseDTO` | Returns which of the requested post ids are visible. New facade `VisibilityResult`. |
| 7 | POST | `data/check-visibility-with-comments` | `CheckVisibilityRequestDTO` | `CheckVisibilityWithCommentsResponseDTO` | Same request/response as #6; also resolves comment visibility. |

> **Codegen check (Q5 pattern):** confirm whether any of these response DTOs generate as
> `RootModel[Any]` stubs with a typed `…Model`/`…1` sibling (as happened for several DTOs in M3/M5/M9).
> The facade and API layer must bind to the typed variant. Resolve when the generated module is
> inspected — the pinned swagger already contains all seven (no regeneration needed unless a field
> is missing).

## 3. Deliverables

- **`models/facade/posts.py`** — add `PostCapabilities`, `PostHistoryEvent`, `VisibilityResult`
  facades (composition over the generated DTOs, `extra="ignore"`, `.raw` escape hatch). Reuse the
  existing `Post` facade for #1, #4, #5.
- **`api/posts.py`** — add to `PostsAPI`:
  - `get_by_client_uid(client_uid: str, *, load_main_attachment: bool = False, ...) -> Post`
  - `capabilities(post_id: int) -> PostCapabilities`
  - `history(post_id, *, page_token=None, page_size=None, **filters)` + `history_raw(...)` + `iterate_history(...)`
  - `global_stream(*, page_token=None, page_size=None, **filters)` + `iterate_global_stream(...)`
  - `community_list(community_id, *, page_token=None, page_size=None, **filters)` + `community_list_raw(...)` + `iterate_community_list(...)`
  - `check_visibility(post_ids: list[int]) -> VisibilityResult` + `check_visibility_raw(...)`
  - `check_visibility_with_comments(post_ids: list[int]) -> VisibilityResult` + raw
  - Follow the established "one method, one shape" + `*_raw` escape-hatch convention.
- **`cli/posts.py`** — new subcommands wired through `render_output` (so `--output`, `--full`,
  `--fields`, `--web-url`, `--export` all compose automatically):
  - `posts get-by-client-uid <clientUid>`
  - `posts capabilities <postId>`
  - `posts history <postId> [--all]`
  - `posts global-stream [--all]`
  - `posts community-list --community <id> [--all]`  *(name disambiguated from `posts list`)*
  - `posts check-visibility <id...>` / `posts check-visibility --with-comments`
- **Models** — re-export new facades from `models/facade/__init__.py` and `models/__init__.py`.

## 4. Acceptance criteria

- `respx` unit tests for all seven endpoints (URL, headers, body camelCase shaping, parsing) in
  `tests/unit/test_api_posts.py`; pagination tests for #3/#4/#5 via the `iterate_*` helpers.
- Facade unit tests in `tests/unit/test_facade_posts.py` (new capability/history/visibility facades).
- CLI snapshot tests (syrupy, table + json) in `tests/unit/test_cli_posts.py`, incl. `--web-url`
  on single-post commands and `--all` pagination.
- Contract tests in `tests/contract/test_models.py` — schema-superset + facade smoke for the new
  request/response DTOs.
- 1–2 new JSON fixtures per response shape under `tests/fixtures/payloads/`.
- Integration smoke (opt-in) in `tests/integration/` reading a known post's capabilities/history.
- Quality gates green: `ruff check`/`format`, `mypy src` strict, `pytest --cov --cov-fail-under=85`.
- Docs: `docs/cli.md` (new commands), `docs/api/posts.md` (mkdocstrings picks up new methods),
  README feature line if warranted.

## 5. Open questions

- **Q-v0.2-1 — `global-stream` request shape.** Swagger shows no body `$ref` for `global-stream`;
  confirm whether filters/pagination go via query params or an undocumented body at codegen/integration.
- **Q-v0.2-2 — `community-list` vs `list/community` semantics.** Both return `PagedListPostsResponseDTO`
  but take different request DTOs. Document the practical difference (filtered vs basic) in the CLI
  help and `docs/cli.md` to avoid the `users me` / `users profile` style confusion.
- **Q-v0.2-3 — capabilities field set.** Inspect `GetPostCapabilitiesResponseDTO` to decide which
  fields the curated CLI table shows vs `--full`.
