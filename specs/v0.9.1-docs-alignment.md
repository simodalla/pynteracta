# pynteracta v0.9.1 — Documentation alignment & config fixes (M23)

> **Status: PLANNING — ⏳ In progress.** Corrective release: no new surface. Aligns `README.md` and
> `docs/` with the code as shipped in v0.9.0, and fixes two configuration behaviours that the docs
> promise but the code does not deliver. Follows the conventions of the
> [foundation spec](v0.1-foundation.md), the [v0.9 spec](v0.9-minor-enhancements.md) (M22) and the
> patterns logged in [`PROGRESS.md`](../PROGRESS.md) (M22 docs snippet fixes).
> Index: [`ROADMAP.md`](../ROADMAP.md).

## 1. Objective

An audit performed on 2026-09-11 (README + every file under `docs/`, each snippet and flag checked
against `src/`) found that the entry pages (`README.md`, `docs/index.md`, `docs/quickstart.md`) are
still written for v0.1.0, that several Python snippets raise at runtime, that a handful of CLI
examples fail as written, and that two documented configuration features do not exist in the code.

This release makes every statement in `README.md` and `docs/` true for the v0.9.x code. Where the
gap is in the **code**, the decision is recorded per item in §4: one gap is closed by fixing the code
(`log_level` from profile/env), one by removing the promise from the docs (`PYNTERACTA_PROFILE`).

Targets a **patch bump 0.9.0 → 0.9.1**: the commits are `docs:` plus one `fix:`; there is no
`feat:`, so `python-semantic-release` computes a patch (see **D-v0.9.1-1**).

## 2. Endpoints in scope

No endpoints. This release touches documentation, `src/pynteracta/cli/__init__.py`,
`src/pynteracta/cli/_common.py` (log-level resolution) and their tests only.

> **Out of scope:** any API-layer change, any new CLI flag, `posts community-list` filter wiring.

### D. Code fix — honour `log_level` from profile and environment

- **`cli/__init__.py`** — `--log-level` default becomes `None`. Resolution order at startup:
  explicit `--log-level` > `PYNTERACTA_LOG_LEVEL` / profile `log_level` (already merged by
  `resolve_profile`) > `INFO`. Both call sites (`cli/__init__.py` callback and
  `_common.build_client`) use the resolved value; `setup_default_logging` must not be called twice
  with different levels.
- **Tests** — `tests/unit/test_cli_config.py` (or a new `test_cli_root.py` case): profile
  `log_level = "DEBUG"` → logger level DEBUG; `--log-level WARNING` overrides it; default INFO.
- **Docs** — `docs/configuration.md` row for `log_level` stays, now accurate.

### E. Doc-snippet import check (new unit test)

- **`tests/unit/test_docs_snippets.py`** (new) — collects every fenced ```` ```python ```` block in
  `README.md` and `docs/**/*.md` and, for each block:
  1. compiles it (`compile(src, path, "exec")`) — a syntax error fails the test naming file and
     block index;
  2. walks the AST for `import x` / `from x import y` statements whose root package is `pynteracta`
     and verifies with `importlib.import_module` that the module exists and, for `from … import y`,
     that `y` is an attribute of it (catches `from pynteracta import InteractaClient`);
  3. for attribute chains that start with an imported `pynteracta` name and are **class or module
     attributes** resolvable statically (e.g. `InteractaClient.from_service_account`), verifies the
     attribute exists on the imported object. Instance attributes (`client.users`, `post.title`)
     are **not** checked — they need a live object (D-v0.9.1-8).
- Blocks are **never executed** (they need a tenant). A block can opt out with an HTML comment on
  the line before the fence: `<!-- snippet: skip -->` (for intentionally partial fragments such as
  `creation_timestamp_from=1735689600000`). Fragments that are not valid statements on their own
  must either be made valid or carry the marker; the audit lists the current ones in
  `filtering-posts.md` (§Date filter formats) and `filtering-users.md`.
- The test runs in the default `pytest` invocation (unit, no network) and therefore inside the
  `--cov-fail-under=85` gate; it does not contribute coverage and must not lower it.

## 4. Resolved decisions

- **D-v0.9.1-1 — patch release.** No feature ships; commits are `docs:` and one `fix:`.
  `python-semantic-release` therefore computes **0.9.1**. This is the project's first patch and does
  not contradict the "every feature is a minor" policy, which is about features. Milestone number
  continues the sequence (**M23**).
- **D-v0.9.1-2 — `PYNTERACTA_PROFILE` is removed from the docs, not implemented.** Profile
  selection already has two mechanisms (`--profile`, `current_profile`); a third one adds precedence
  ambiguity for little value. Revisit only on explicit demand.
- **D-v0.9.1-3 — `log_level` from profile/env is fixed in code.** The field exists on `Profile` and
  `_EnvSettings` and is documented; silently ignoring it is a bug, not a doc error.
- **D-v0.9.1-4 — no `-o` global short flag.** Keep `-o` per-command only; fix the prose. Adding a
  global short option is a feature and belongs to a minor.
- **D-v0.9.1-5 — `posts community-list` docs are trimmed, not the command extended.** Wiring the
  request DTO is medium work already tracked as an M22 follow-up.
- **D-v0.9.1-6 — README wheel name is a placeholder.** `pynteracta-<version>-py3-none-any.whl`
  plus a link to the pipeline artifacts; the README no longer needs a touch on every release.
- **D-v0.9.1-7 — the internal GitLab is the canonical repository.** `pyproject.toml`
  `[project.urls]` is aligned to it; docs already point there.
- **D-v0.9.1-8 — doc snippets get a static import/attribute check, not execution.** Syntax, module
  imports, `from … import` names and statically resolvable class/module attributes are verified;
  instance-level attribute use stays a review concern. Opt-out marker `<!-- snippet: skip -->`.
