# pynteracta v0.6.0 — Admin manage edits (read forms) (M19)

> **Status: PLANNING — ⏳ In progress.** Spec for the next minor. Read-only, additive. No change to existing flows.
> Follows the conventions of the [foundation spec](v0.1-foundation.md), the
> [groups & hashtags spec](v0.5-groups-hashtags.md), and the patterns logged in
> [`PROGRESS.md`](../PROGRESS.md) (M5 resource clients, M16 attachments, M17 tasks, M18 groups/hashtags).
> Index: [`ROADMAP.md`](../ROADMAP.md).

## 1. Objective

Expose the **admin manage edit** surfaces (read-form helpers) for workspaces, catalogs, catalog entries, and user credentials. These endpoints return the full entity state plus an `occToken` for optimistic concurrency control, used by write operations (deferred to v1.0+). After v0.5.0 added groups and hashtags, v0.6.0 adds these four admin-only read-form endpoints.

Targets a **minor bump 0.5.0 → 0.6.0** via a `feat:` commit. All existing resource clients unchanged. Introduces one new resource group (`admin_manage`).

## 2. Endpoints in scope

All paths under `{base}/api/external/v2/`.

| # | Method | Path | Request DTO | Response DTO |
|---|---|---|---|---|
| 1 | GET  | `admin/manage/workspaces/{workspaceId}/edit` | – | `GetWorkspaceForEditResponseDTO` |
| 2 | GET  | `admin/manage/catalogs/{catalogId}/edit` | – | `GetCatalogForEditResponseDTO` |
| 3 | GET  | `admin/manage/catalogs/{catalogId}/entries/{entryId}/edit` | – | `GetCatalogEntryForEditResponseDTO` |
| 4 | GET  | `admin/manage/users/{userId}/credentials/edit` | – | `GetUserCredentialsForEditResponseDTO` |

**Codegen stub → typed mapping:**
- All response DTOs are plain `BaseModel` types.
- Response objects carry an `occToken` field (string, nullable) for optimistic concurrency control; will be used by write operations in v1.0+.

> **Out of scope:** write endpoints (`PUT admin/manage/workspaces/{workspaceId}/edit`,
> `PUT admin/manage/catalogs/{catalogId}/edit`,
> `PUT admin/manage/catalogs/{catalogId}/entries/{entryId}/edit`,
> `PUT admin/manage/users/{userId}/credentials/edit`, etc.) — deferred to the v1.0+ write line.
> The `occToken` on each response DTO is carried through `.raw` for future write use.

## 3. Deliverables

- **`models/facade/admin_manage.py`** (new module):
  - `WorkspaceForEdit` — facade over `GetWorkspaceForEditResponseDTO`. Curated: workspace scalar fields (id, name, email, etc.), `occ_token` on `.raw` escape hatch.
  - `CatalogForEdit` — facade over `GetCatalogForEditResponseDTO`. Curated: catalog scalar fields (id, name, description, etc.), `occ_token` on `.raw`.
  - `CatalogEntryForEdit` — facade over `GetCatalogEntryForEditResponseDTO`. Curated: entry scalar fields, nested catalog reference if present, `occ_token` on `.raw`.
  - `UserCredentialsForEdit` — facade over `GetUserCredentialsForEditResponseDTO`. Curated: user credential fields, `occ_token` on `.raw`.
  - Re-export all new types from `models/facade/__init__.py` and `models/__init__.py`.

- **`api/admin_manage.py`** (new module) — `AdminManageAPI(ResourceClient)`:
  - `workspace_for_edit(workspace_id: int) -> WorkspaceForEdit`
  - `catalog_for_edit(catalog_id: int) -> CatalogForEdit`
  - `catalog_entry_for_edit(catalog_id: int, entry_id: int) -> CatalogEntryForEdit`
  - `user_credentials_for_edit(user_id: int) -> UserCredentialsForEdit`

- **`client.py`** — register `self.admin_manage = AdminManageAPI(...)`.

- **`cli/admin_manage.py`** (new Typer sub-app); wired through `render_output`:
  - `admin-manage workspace WORKSPACE_ID`
  - `admin-manage catalog CATALOG_ID`
  - `admin-manage catalog-entry CATALOG_ID ENTRY_ID`
  - `admin-manage user-credentials USER_ID`

## 4. Resolved decisions

- **D-v0.6-1 — resource grouping.** One dedicated resource group (`admin_manage`) housing all four edit endpoints. Mirrors M16/M17/M18 pattern.
- **D-v0.6-2 — endpoint scope.** Four admin-only read-form endpoints; write operations deferred to v1.0+. These are propaedeutic: they fetch the entity state and `occToken` required by future writes.

## 5. Open questions

- **Q-v0.6-1 — facade field curation.** Confirm during implementation which fields from each response DTO should be surfaced on the facade (scalars only, or nested objects too). Document in facade docstrings.
- **Q-v0.6-2 — CLI naming.** Confirm the exact command tree: `pynteracta admin-manage <subcommand>` or alternative grouping.

## 6. Out of scope

- Write operations (PUT) on any admin/manage endpoint — deferred to v1.0+.
- Non-admin manage surfaces (e.g. user self-edit) — separate backlog item.
