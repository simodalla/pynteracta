## 1. Objective

Complete the **filtering and ordering** surface of the system users list endpoint
(`ListSystemUsersRequestDTO`), turning today's opaque `**filters` passthrough into an **explicit,
validated, discoverable** API (typed kwargs + CLI options), while keeping `**filters` as the
documented escape hatch.

This minor adds **no new endpoint**: it deepens `admin/data/users`, already shipped in v0.1.0. It
is the sibling of v0.7.0 (posts), split out to honour the one-group-per-minor cadence.

Targets a **minor bump 0.7.0 → 0.8.0** via a `feat:` commit. Existing call sites keep working: new
kwargs are all optional, `**filters` passthrough is preserved.

## 2. Endpoints in scope

All paths under `{base}/api/external/v2/`. The endpoint already exists — this minor only expands
its parameter surface.

| # | Method | Path | Request DTO | Response DTO |
|---|---|---|---|---|
| 1 | POST | `admin/data/users` | `ListSystemUsersRequestDTO` | `ListSystemUsersResponseDTO` (→ `SystemUserList`) |

**Codegen stub → typed mapping:**
- `ListSystemUsersRequestDTO` is a plain `BaseModel` with ~30 typed filter fields plus
  `orderTypeId` (str) / `orderDesc` (bool) for ordering.
- The user date filters (`creationTimestampFrom/To`, `lastAccessTimestampFrom/To`) are
  epoch-millis `int`.
- `orderTypeId` is described only as "Id campo di ordinamento" — no enumerated value set in the DTO
  (see Q-v0.8-2).

## 3. Deliverables

### Library — users (`api/users.py`)
- Add curated explicit kwargs to `list` (and forward through `iterate`):
  `full_text_filter`, `status_filter: list[int] | None`, `workspace_ids: list[int] | None`,
  `community_ids: list[int] | None`, `creation_timestamp_from`, `creation_timestamp_to`,
  `last_access_timestamp_from`, `last_access_timestamp_to`, `role: str | None`,
  `order_by: str | None` (maps `orderTypeId`), `order_desc: bool | None`.
- The remaining ~20 `ListSystemUsersRequestDTO` fields (businessUnit/area ids, manager ids, lang,
  timezone, people-section flags, name/email prefixes, loginProvider, …) stay reachable via the
  preserved `**filters` passthrough.

### Shared helpers (`api/_utils.py`)
- **Reuse the date coercion helper introduced in v0.7.0** (`int` / `datetime` / ISO-8601 `str` →
  epoch-millis) for the `*_timestamp_from/to` kwargs.
- Reuse `snake_to_camel` for `--filter key=value` key conversion (CLI).

### CLI (`cli/users.py`)
- `users list`: add `--full-text`, `--status` (repeatable), `--workspace` (repeatable),
  `--community` (repeatable), `--role`, `--created-from`, `--created-to`, `--order-by`, `--desc`,
  and a repeatable `--filter key=value`. (Extend the existing minimal `users` sub-app.)

### Tests & docs
- Unit tests (respx) for: user curated-kwarg → DTO mapping, date coercion (int / datetime / ISO),
  `--filter key=value` parsing + snake→camel.
- Contract test assertions that the new kwargs serialize to fields present on the pinned DTO.
- Docs: update `docs/cli.md` (new options) and the users API reference page.

## 4. Resolved decisions

- **D-v0.8-1 — split from posts.** Users filter completion is its own minor (after v0.7.0 posts) to
  honour the one-group-per-minor cadence.
- **D-v0.8-2 — curated subset + passthrough.** Explicit typed kwargs only for the common filters;
  `**filters` remains the documented escape hatch for the long tail (~20 fields).
- **D-v0.8-3 — date filters accept int + datetime/ISO.** `*_timestamp_from/to` kwargs coerce
  `datetime`/ISO-8601 to epoch-millis; plain `int` passes through unchanged. Reuses the helper
  introduced in v0.7.0.
- **D-v0.8-4 — `--filter` keys are snake_case.** Converted via `snake_to_camel`, consistent with
  the explicit kwargs and with v0.7.0.

## 5. Open questions

- **Q-v0.8-1 — curated subset boundary.** Confirm the exact set of promoted kwargs at implementation
  time; the proposed list above is the candidate. Anything not promoted stays in `**filters`.
- **Q-v0.8-2 — `order_by` / `orderTypeId` allowed values.** No enumerated list in the DTO. Decide
  whether to validate client-side (like posts) or pass through unvalidated; default to passthrough
  unless a known value set surfaces from a real tenant.
- **Q-v0.8-3 — `--filter` value typing on CLI. RESOLVED (per v0.7-3).** `--filter key=value` is
  **string-only**; `int`/`bool`/`list` fields are reached via the dedicated typed flags
  (`--status`, `--workspace`, `--community`, `--order-by`, `--desc`, …), not via `--filter`.

- Any write/mutation surface.
- Promoting the full ~30-field filter set to explicit kwargs (long tail stays in `**filters`).
