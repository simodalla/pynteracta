# pynteracta v0.9.2 — Migration to GitHub (M24)

> **Status: PLANNED.** Infrastructure release: no API surface, no CLI change. Moves the canonical
> repository from the internal GitLab to a public GitHub repository, replaces GitLab CI with
> GitHub Actions, and publishes the documentation site and release artifacts from there.
> Supersedes **D-v0.9.1-7**. Follows the conventions of the
> [foundation spec](v0.1-foundation.md) §17 (CI/CD) and the
> [v0.9.1 spec](v0.9.1-docs-alignment.md) (M23). Index: [`ROADMAP.md`](../ROADMAP.md).

## 1. Objective

v0.9.1 established the internal GitLab (`gitlab.unionerenolavinosamoggia.bo.it/ucrls/pynteracta`)
as the canonical repository (**D-v0.9.1-7**). That decision is now reversed: the project moves to
**`github.com/simodalla/pynteracta`**, public, with the internal GitLab retained as a
synchronised mirror (**D-v0.9.2-2**).

Three things motivate the move. The self-hosted GitLab CI never became fully operational — the
runner tag and registry image placeholders opened as **Q11** in the foundation spec were still
unresolved at v0.9.1, so the `.gitlab-ci.yml` matrix job had no confirmed runner. Wheel
distribution depended on browsing pipeline artifacts, which **D-v0.9.1-6** had already flagged as
awkward. And `mkdocs.yml` `site_url` still pointed at `pynteracta.gitlab.io`, logged as an open
follow-up in [`PROGRESS.md`](../PROGRESS.md) (M23, §Follow-ups) because no internal Pages instance
existed.

A public GitHub repository closes all three at once: hosted runners remove the Q11 placeholders,
GitHub Releases replace artifact browsing, and GitHub Pages gives the docs a real published URL.

Targets a **patch bump 0.9.1 → 0.9.2**: commits are `ci:`, `docs:` and `chore:`, with no `feat:`,
so `python-semantic-release` computes a patch (**D-v0.9.2-1**, same reasoning as D-v0.9.1-1).

## 2. Endpoints in scope

No endpoints. This release touches repository infrastructure, `.github/workflows/`, `scripts/`,
`pyproject.toml` `[project.urls]`, `mkdocs.yml`, `README.md`, `CONTRIBUTING.md` and `docs/` only.
No file under `src/pynteracta/` changes, and no test is added or modified.

> **Out of scope:** any API-layer change, any CLI flag, PyPI publication (stays a 1.0 target).

## 3. Deliverables

### A. Git migration

- Create the public repository `github.com/simodalla/pynteracta` (Apache-2.0, topics: `python`,
  `interacta`, `api-client`, `cli`, `rest-api`, `httpx`, `pydantic`).
- Push `main` (123 commits) and all ten tags `v0.1.0`…`v0.9.1` unchanged. `main` must resolve to
  the same SHA on both remotes.
- Remotes on the developer machine: `origin` → GitHub, `gitlab` → internal GitLab.
- **No history rewrite** (**D-v0.9.2-3**). A pre-publication audit of the full history found no
  credential: `tests/fixtures/sa_key.json` is a synthetic RSA-2048 fixture (`private_key_id: 42`,
  `client_id: 1001`, no `client_email` or `project_id`), and every payload fixture uses
  `example.com` / `example.it` hosts. `.secrets/` and `*.env` were never committed.
- The 34 stale local branches are **not** pushed: all are already merged into `main`, so they carry
  no unique history (**D-v0.9.2-4**).

### B. `.github/workflows/ci.yml` — replaces `.gitlab-ci.yml`

One job per former stage, on `push` to `main`, on every `pull_request`, and `workflow_dispatch`;
concurrency group per ref with `cancel-in-progress`.

| Job | Command | Notes |
|---|---|---|
| `lint` | `ruff check .` + `ruff format --check .` | |
| `type-check` | `mypy src` | strict |
| `test-unit` | `pytest -m "not integration and not contract" --cov --cov-fail-under=85` | matrix `3.12`, `3.13`, `fail-fast: false`; uploads `coverage.xml` on 3.12 |
| `test-contract` | `pytest -m contract` | |
| `build` | `uv build` | `needs` all of the above; uploads `dist/*.whl` + `dist/*.tar.gz`, 90-day retention |
| `docs` | `mkdocs build --strict` | uploads `site/`, 7-day retention |

All jobs run on `ubuntu-latest` with `astral-sh/setup-uv@v5` (`enable-cache: true`) and
`uv sync --frozen`. The matrix job sets the interpreter through `setup-uv`'s `python-version`,
which resolves the Q11 note in the foundation spec §17 about the runner having to provide both
interpreters (**D-v0.9.2-5**).

- Delete `.gitlab-ci.yml`.

### C. `.github/workflows/docs.yml` — GitHub Pages

- On `push` to `main` and `workflow_dispatch`; `permissions: pages: write`, `id-token: write`;
  concurrency group `pages` with `cancel-in-progress: false`.
- `mkdocs build --strict` → `actions/upload-pages-artifact` → `actions/deploy-pages`.
- Pages configured with `build_type: workflow`; published at
  **`https://simodalla.github.io/pynteracta/`**, which becomes `mkdocs.yml` `site_url` and closes
  the M23 follow-up.

### D. `.github/workflows/release.yml` — GitHub Releases

- On `push` of tags matching `v*`; `permissions: contents: write`.
- `uv build`, then `softprops/action-gh-release@v2` attaches `dist/*.whl` and `dist/*.tar.gz` with
  `generate_release_notes: true`.
- This replaces "download the wheel from the latest pipeline" as the distribution channel and makes
  the placeholder wheel filename of **D-v0.9.1-6** resolvable from a stable release page.
- Phase 6 of [`WORKFLOW.md`](../WORKFLOW.md) is unchanged: `semantic-release` still cuts the tag
  locally; the workflow only reacts to the tag being pushed.

### E. GitLab mirror

- `.github/workflows/mirror-gitlab.yml` — pushes `main` and tags to the internal GitLab. Gated on
  `vars.GITLAB_MIRROR_ENABLED == 'true'` and **disabled by default**: hosted runners cannot resolve
  the internal hostname, so the job is only useful from a self-hosted runner
  (`secrets.GITLAB_MIRROR_SSH_KEY`, `vars.GITLAB_MIRROR_HOST`, `vars.GITLAB_MIRROR_URL`).
- `scripts/mirror_to_gitlab.sh` — the working path in the meantime: pushes `main` + tags to the
  `gitlab` remote from a machine on the internal network (**D-v0.9.2-6**).

### G. Dependabot

`.github/dependabot.yml` configures three ecosystems, all weekly (Monday 06:00 Europe/Rome) with
grouped pull requests and a limit of 5 open PRs each:

| Ecosystem | Covers | Commit prefix | Groups |
|---|---|---|---|
| `uv` | `pyproject.toml` constraints + `uv.lock` | `build` (runtime), `chore` (dev) | `python-runtime`, `python-dev` (minor+patch), `python-security` |
| `github-actions` | the 7 actions used by the workflows | `ci` | `github-actions` |
| `pre-commit` | hook `rev`s in `.pre-commit-config.yaml` | `chore` | `pre-commit` |

- **Commit prefixes are mandatory, not cosmetic** (**D-v0.9.2-9**). The `conventional-pre-commit`
  hook and `commit_parser = "conventional"` mean an unprefixed bot commit would be unclassifiable
  by `git-cliff` and `python-semantic-release`. `build:` and `chore:` carry no version impact;
  `ci:` matches the existing `cliff.toml` CI group.
- Major updates are **not** grouped: they arrive as individual PRs so a breaking bump is reviewed
  on its own.
- Labels `dependencies`, `python`, `github-actions`, `pre-commit` are created on the repository.
- Repository-level **Dependabot alerts** and **security updates** are enabled via the API; these
  are independent of the config file and cover security advisories regardless of the weekly
  schedule. Secret scanning with push protection is on by default for the public repository.
- `ci.yml` declares `permissions: contents: read`. Dependabot PRs run with a read-only token, and
  the CI jobs need nothing more (**D-v0.9.2-10**).

### H. Gate for this release

Unchanged from the standard gate — `ruff check .`, `ruff format --check .`, `mypy src`,
`pytest --cov --cov-fail-under=85`, `mkdocs build --strict` — plus three migration-specific checks:

- `main` resolves to the same SHA on `origin` and `gitlab`, and all ten tags are present on GitHub.
- Every workflow file parses as YAML, and no `gitlab` reference remains in any non-frozen tracked
  file (`git grep -i gitlab` excluding `uv.lock`, `PROGRESS.md`, `CHANGELOG.md`, `specs/`, and the
  mirror workflow/script, which reference it by design).
- `.github/dependabot.yml` parses as YAML and every label it references exists on the repository.

## 4. Resolved decisions

- **D-v0.9.2-1 — patch release.** No feature ships; commits are `ci:`, `docs:` and `chore:`.
  `python-semantic-release` computes **0.9.2**. Milestone continues the sequence (**M24**).
- **D-v0.9.2-2 — GitHub is the canonical repository; GitLab becomes a mirror. Supersedes
  D-v0.9.1-7.** The internal GitLab stays synchronised as a secondary remote rather than being
  archived, so internal tooling that still points at it keeps working.
- **D-v0.9.2-3 — no history rewrite before going public.** The full-history audit found no real
  credential (see §3.A). `git filter-repo` would rewrite all 123 commit SHAs and invalidate the ten
  existing tags for no security benefit.
- **D-v0.9.2-4 — stale local branches are not migrated.** All 34 are merged into `main`; pushing
  them would add clutter without preserving any unique history. They remain on the developer
  machine as an archive.
- **D-v0.9.2-5 — hosted runners, closing Q11.** The foundation spec left the self-hosted runner
  tag and registry image as placeholders to be filled by the platform owner. `ubuntu-latest` plus
  `astral-sh/setup-uv` makes both moot; Q11 is answered by removal, not by configuration.
- **D-v0.9.2-6 — the mirror runs from a local script, not from CI, by default.** Hosted runners
  cannot reach the internal hostname. The workflow exists for a future self-hosted runner but is
  opt-in via a repository variable, so it never fails a build by default.
- **D-v0.9.2-7 — frozen documents keep their GitLab references.** `PROGRESS.md`, `CHANGELOG.md`
  and shipped specs are historical records. Consistent with the freeze rule in `WORKFLOW.md`.
- **D-v0.9.2-8 — install examples pin an explicit tag.** `git+https://…@v0.9.1` rather than
  `@main`, so a copied command installs a released version. The pinned tag is refreshed when it
  drifts more than one minor behind, not on every release (consistent with D-v0.9.1-6's intent of
  not touching the README each release).

- **D-v0.9.2-9 — Dependabot commits carry Conventional Commits prefixes.** `build:` for runtime
  dependencies, `chore:` for dev dependencies and pre-commit hooks, `ci:` for actions. Without a
  prefix the commit fails the `conventional-pre-commit` gate and lands unclassified in the
  changelog. None of the three prefixes triggers a version bump, which is correct for dependency
  maintenance.
- **D-v0.9.2-10 — grouped PRs, weekly, with majors ungrouped.** Seven actions and roughly fifteen
  dev dependencies would otherwise produce a stream of single-dependency PRs. Grouping minor and
  patch updates per ecosystem keeps the review surface to about three PRs a week, while major
  bumps stay individual so a breaking change is never buried in a group.

## 5. Open questions

- **Q-v0.9.2-1 — repository visibility (RESOLVED 2026-09-12):** public. The project already
  carries Apache-2.0 and the verbatim third-party trademark disclaimer, and the history audit
  (§3.A) found nothing tenant-specific. Public also makes Actions and Pages free.
- **Q-v0.9.2-2 — fate of the internal GitLab (RESOLVED 2026-09-12):** kept as a synchronised
  mirror, see D-v0.9.2-2.
- **Q-v0.9.2-3 — branch protection on `main`.** Not configured in this release. Requiring the CI
  jobs to pass before merge is desirable but interacts with the solo-maintainer workflow, where
  `semantic-release` commits the version bump directly to `main`. Revisit when a second maintainer
  joins, or once the release flow is confirmed green on GitHub.
- **Q-v0.9.2-4 — does PyPI publication move earlier now?** A public repository plus a working
  release workflow lowers the cost of publishing, and trusted publishing (OIDC) would need no
  stored token. Still deferred to 1.0 per the roadmap; re-evaluate if external users appear.

## 6. Out of scope

- PyPI publication and trusted publishing (Q-v0.9.2-4; 1.0 target per `ROADMAP.md`).
- Branch protection and required status checks (Q-v0.9.2-3).
- Migration of GitLab issues, merge requests or wiki — none exist; the project tracks work in
  `ROADMAP.md`, `specs/` and `PROGRESS.md`.
- CodeQL and any other code-scanning configuration; only Dependabot ships here (§3.G).
- Archiving or decommissioning the internal GitLab (D-v0.9.2-2 keeps it as a mirror).
- Any change under `src/pynteracta/` or `tests/`.
