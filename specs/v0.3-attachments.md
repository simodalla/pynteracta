# pynteracta v0.3.0 — Attachments read (M16)

> **Status: SHIPPED — v0.3.0 (2026-06-05).** Read-only, additive. No change to
> existing flows. Follows the conventions of the [foundation spec](v0.1-foundation.md) and the
> [posts read-completeness spec](v0.2-read-surface.md), and the patterns logged in
> [`PROGRESS.md`](../PROGRESS.md) (M5 resource clients, M9 communities/catalogs, M15 posts read).
> Index: [`ROADMAP.md`](../ROADMAP.md).

## 1. Objective

Expose the **attachments read surface** of the Interacta API as a new first-class resource. After
v0.2.0 rounded out the posts read surface, v0.3.0 adds the three read endpoints that let callers
list a post's attachments, fetch a single attachment's detail, and check attachment visibility.

Targets a **minor bump 0.2.0 → 0.3.0** via a `feat:` commit. Service-account and Google OAuth2
flows unchanged; all existing resource clients unchanged. This introduces a **new resource group**
(`attachments`) rather than extending `PostsAPI`.

## 2. Endpoints in scope

All paths under `{base}/api/external/v2/`.

| # | Method | Path | Request DTO | Response DTO | Notes |
|---|---|---|---|---|---|
| 1 | POST | `communication/attachments/data/posts/{postId}/attachments-list` | `ListPostAttachmentsByPostIdRequestDTO` | `ListPostAttachmentsResponseDTO` | List a post's attachments. Paginated → `PageIterator`. `items` = `ListPostAttachmentsElementDTO`. Response carries extra aggregate counts (`canAddAttachment`, `imageAttachmentsCount`, `videoAttachmentsCount`, `audioAttachmentsCount`, `documentsAttachmentsCount`). New facade `PostAttachment`. |
| 2 | GET | `communication/posts/data/attachment-detail-by-id/{attachmentId}` | – | `GetPostAttachmentDetailResponseDTO` | Single attachment detail. Returns `attachmentData` (`PostAttachmentDataDTO`) + parent `post` (`PostBaseInfoDTO`). New facade `AttachmentDetail` (or `PostAttachment` + `.post`). **Note:** lives under the `posts/data/*` prefix but belongs to the attachments resource group (decided — see D-v0.3-1). |
| 3 | POST | `communication/attachments/data/check-visibility` | `CheckVisibilityRequestDTO` | `CheckVisibilityResponseDTO` | Returns which of the requested attachment ids are visible (`{ ids: [...] }`). New thin facade `AttachmentVisibility` — **not** the v0.2 `VisibilityResult` (decided — see D-v0.3-2). |

> **Codegen check (Q5 pattern):** confirm whether any of these response DTOs generate as
> `RootModel[Any]` stubs with a typed `…Model`/`…1` sibling (as happened in M3/M5/M9/M15). The
> facade and API layer must bind to the typed variant. The pinned `tests/fixtures/swagger.json`
> already contains all three — no regeneration needed unless a field is missing from
> `src/pynteracta/models/generated/external_v2.py`.

> **Out-of-scope sibling (do not implement):** `PUT communication/posts/manage/edit-post-attachments/{postId}`
> and `POST core/storage/upload-new-attachment` are **write** endpoints — deferred to the future
> write line.

## 3. Deliverables

- **`models/facade/attachments.py`** (new module) — `PostAttachment` facade (composition over
  `ListPostAttachmentsElementDTO` / `PostAttachmentDataDTO`, which share the same core shape:
  `id`, `name`, `contentMimeType`, `size`, `type`, `downloadable`, `versionNumber`, the
  `temporaryContent*Link` URLs, `creatorUser`, `creationTimestamp`, `hashtags`, …), with
  `extra="ignore"` and `.raw` escape hatch. Add `AttachmentDetail` wrapping `attachmentData` +
  `post` (`PostBaseInfoDTO`), or expose the parent post via a `.post` property on `PostAttachment`.
  Add a thin `AttachmentVisibility` facade over `CheckVisibilityResponseDTO` (`ids: list[int]`)
  — kept separate from the v0.2 `VisibilityResult` (D-v0.3-2).
- **`api/attachments.py`** (new module) — `AttachmentsAPI(ResourceClient)`:
  - `list_for_post(post_id: int, *, page_token=None, page_size=None, types=None,
    entity_types=None, mime_types=None, mime_type_category=None, order_by=None, order_desc=None) -> ...`
    + `list_for_post_raw(req: ...)` + `iterate_for_post(post_id, **filters)` (returns
    `PageIterator[PostAttachment]`). Curated explicit-kwarg filter set per D-v0.3-4; the niche
    filters (`aiSupportedFilter`, `postFilePickerFieldId`, `wfScreenFilePickerFieldId`, `language`)
    are reachable only via `list_for_post_raw`.
  - `get(attachment_id: int) -> AttachmentDetail`
  - `check_visibility(attachment_ids: list[int]) -> AttachmentVisibility` + `check_visibility_raw(...)`
  - Follow the established "one method, one shape" + `*_raw` escape-hatch convention; use the
    `_utils` snake→camel body/query builders.
- **`client.py`** — register `self.attachments = AttachmentsAPI(...)` on `InteractaClient`.
- **`cli/attachments.py`** (new Typer sub-app) — wired through `render_output` (so `--output`,
  `--full`, `--fields`, `--export` all compose; **`--web-url` is intentionally omitted** for this
  group per D-v0.3-3b). Curated table = metadata only, temporary links via `--full`/`--export`/json
  (D-v0.3-3a). Registered on the top-level CLI:
  - `attachments list --post <id> [--all]` *(or `attachments list <postId>`)*
  - `attachments get <attachmentId>`
  - `attachments check-visibility <id...>`
- **Models** — re-export new facades from `models/facade/__init__.py` and `models/__init__.py`
  (and their `__all__`).

## 5. Resolved decisions

- **D-v0.3-1 — resource grouping vs URL prefix.** *Resolved:* group **all three** endpoints under a
  single `AttachmentsAPI` / `attachments` CLI group, including `attachment-detail-by-id` even though
  it lives under the `communication/posts/data/*` prefix. Do **not** split it into `PostsAPI`.
  Document the chosen home (and the URL-vs-group mismatch) in `docs/cli.md`.
- **D-v0.3-2 — visibility facade.** *Resolved:* add a **thin separate `AttachmentVisibility`
  facade** over `CheckVisibilityResponseDTO` (`ids: list[int]`); do **not** reuse the v0.2
  `VisibilityResult` (which wraps the richer `CheckVisibilityWithCommentsResponseDTO`).
- **D-v0.3-3a — temporary links in CLI output.** *Resolved:* the curated CLI table shows **metadata
  only** (`id`, `name`, `contentMimeType`, `size`, `type`); the short-lived `temporaryContent*Link`
  download/preview URLs are exposed **only** via `--full`, `--fields`, `--export` and `json` output,
  never in the default table. Keeps the default view scannable and the syrupy snapshots stable
  (ephemeral signed URLs stay out of the default rendering).
- **D-v0.3-3b — no `--web-url` for the attachments group.** *Resolved:* **omit** `--web-url` from the
  `attachments` commands. A bare attachment has no canonical web deep-link, and `WebUrls` targets
  posts; do not synthesize a post URL for an attachment. (`--output`, `--full`, `--fields`,
  `--export` still compose as usual.)
- **D-v0.3-4 — `list_for_post` filter surface.** *Resolved:* surface a **curated subset** as explicit
  kwargs — `types`, `entity_types`, `mime_types`, `mime_type_category`, `order_by`, `order_desc` —
  and leave the niche filters (`ai_supported_filter`, `post_file_picker_field_id`,
  `wf_screen_file_picker_field_id`, `language`) reachable only via `list_for_post_raw(req)`. Mirror
  the explicit kwargs as CLI options. **Sub-note:** swagger types `order_by` as a free `string`;
  verify the valid value set at implementation time and document it in the CLI help.
