# pynteracta v0.5.0 — Groups & Hashtags read (M18)

> **Status: PLANNED.** Spec for the next minor. Read-only, additive. No change to existing flows.
> Follows the conventions of the [foundation spec](v0.1-foundation.md), the
> [attachments spec](v0.3-attachments.md), and the patterns logged in
> [`PROGRESS.md`](../PROGRESS.md) (M5 resource clients, M16 attachments, M17 tasks).
> Index: [`ROADMAP.md`](../ROADMAP.md).

## 1. Objective

Expose the **groups** and **community hashtags** read surfaces as two new first-class resource
groups. After v0.4.0 added tasks, v0.5.0 adds group listing/member listing/group-for-edit and
community hashtag listing. Both are admin/data and admin/manage endpoints.

Targets a **minor bump 0.4.0 → 0.5.0** via a `feat:` commit. All existing resource clients
unchanged. Introduces two new resource groups (`groups`, `hashtags`).

## 2. Endpoints in scope

All paths under `{base}/api/external/v2/`.

| # | Method | Path | Request DTO | Response DTO |
|---|---|---|---|---|
| 1 | POST | `admin/data/groups` | `ListSystemGroupsRequestDTO` | `ListSystemGroupsResponseDTO` |
| 2 | POST | `admin/data/groups/{groupId}/members` | `ListGroupMembersRequestDTO` | `ListGroupMembersResponseDTO` |
| 3 | GET  | `admin/manage/groups/{groupId}/edit` | – | `GetGroupForEditResponseDTO` |
| 4 | POST | `admin/data/communities/{communityId}/hashtags` | `AdminListHashtagsRequestDTO` | `AdminListHashtagsResponseDTO` |

**Codegen stub → typed mapping:**
- `ListSystemGroupsElementDTO` → `RootModel[Any]` stub; bind to `ListSystemGroupsElementDTOModel`.
- `AdminHashtagDTOModel` → `RootModel[Any]` stub; bind underlying `AdminHashtagDTO` (plain BaseModel at line 133).
- `TagDTO` → `RootModel[Any]` stub; bind to `TagDTO1`.
- `UserDTO` → `RootModel[Any]` stub; bind to `UserDTOModel` for group members.
- `GetGroupForEditResponseDTO` is a plain `BaseModel`.
- All request DTOs are plain `BaseModel`.

> **Out of scope:** write endpoints (`POST admin/manage/groups/create`,
> `PUT admin/manage/groups/{groupId}/edit`, `DELETE admin/manage/groups/{groupId}/delete`,
> `POST admin/manage/groups/{groupId}/members/add`, etc.) — deferred to the write line.
> The `occToken` on `GetGroupForEditResponseDTO` is carried through `.raw` for future write use.

## 3. Deliverables

- **`models/facade/groups.py`** (new module):
  - `Group` — facade over `ListSystemGroupsElementDTOModel`. Curated: `id`, `name`, `email`,
    `description`, `members_count`, `visible`, `deleted`, `creation_timestamp`. `tags` exposed
    via `tags_typed` property (list of `Tag` sub-facade). `.raw` escape hatch.
  - `Tag` — thin facade over `TagDTO1`: `id`, `name`, `visible`.
  - `GroupList` — facade over `ListSystemGroupsResponseDTO`; `items_typed` → `list[Group]`.
  - `GroupMember` — thin facade over `UserDTOModel`. Curated: `id`, `firstName`, `lastName`,
    `fullName`, `email`. `.raw` escape hatch.
  - `GroupMemberList` — facade over `ListGroupMembersResponseDTO`; `members_typed` → `list[GroupMember]`.
  - `GroupForEdit` — facade over `GetGroupForEditResponseDTO`. Curated same scalars as `Group`
    plus `occToken` on `.raw`. `members_typed` → `list[GroupMember]`.
  - Re-export all new types from `models/facade/__init__.py` and `models/__init__.py`.

- **`models/facade/hashtags.py`** (new module):
  - `Hashtag` — thin facade over `AdminHashtagDTO`. Curated: `id`, `name`, `community_id`,
    `external_id`, `deleted`. `.raw` escape hatch.
  - `HashtagList` — facade over `AdminListHashtagsResponseDTO`; `items_typed` → `list[Hashtag]`.
  - Re-export from `models/facade/__init__.py` and `models/__init__.py`.

- **`api/groups.py`** (new module) — `GroupsAPI(ResourceClient)`:
  - `list(*, page_token, page_size, full_text_filter, status_filter, workspace_ids, order_by, order_desc) -> GroupList`
  - `list_raw(req: ListSystemGroupsRequestDTO) -> GroupList`
  - `iterate(*, ...) -> PageIterator[Group]`
  - `list_members(group_id, *, page_token, page_size) -> GroupMemberList`
  - `iterate_members(group_id, *, page_size) -> PageIterator[GroupMember]`
  - `get_for_edit(group_id: int) -> GroupForEdit`

- **`api/hashtags.py`** (new module) — `HashtagsAPI(ResourceClient)`:
  - `list_for_community(community_id, *, page_token, page_size, name, include_deleted, order_by, order_desc) -> HashtagList`
  - `list_for_community_raw(community_id, req: AdminListHashtagsRequestDTO) -> HashtagList`
  - `iterate_for_community(community_id, *, ...) -> PageIterator[Hashtag]`

- **`client.py`** — register `self.groups = GroupsAPI(...)` and `self.hashtags = HashtagsAPI(...)`.

- **`cli/groups.py`** (new Typer sub-app), `cli/hashtags.py` (new Typer sub-app); both wired
  through `render_output`:
  - `groups list` — with `--web-url` (links to admin group page via `WebUrls.group()` if
    available, else omit or use a plain URL — see Q-v0.5-1)
  - `groups members GROUP_ID`
  - `groups get GROUP_ID` (calls `get_for_edit`)
  - `hashtags list COMMUNITY_ID`

## 4. Resolved decisions

- **D-v0.5-1 — resource grouping.** Two dedicated resource groups (`groups`, `hashtags`) rather
  than folding into an existing resource. Mirrors M16/M17 pattern.
- **D-v0.5-2 — `GroupMember` vs reusing `UserProfile`.** Introduce a thin `GroupMember` facade
  rather than reusing `UserProfile`, since `GetGroupForEditResponseDTO.members` is `list[UserDTO]`
  (opaque stubs) whereas `UserProfile` wraps `UserProfileInfoDTO1`. Keep them separate.
- **D-v0.5-3 — `AdminHashtagDTO` is already a typed BaseModel.** The response items are
  `list[AdminHashtagDTOModel]` (a `RootModel[Any]` stub), but the underlying typed sibling is the
  plain `AdminHashtagDTO` at line 133 of `external_v2.py` — bind the facade to that.

## 5. Open questions

- **Q-v0.5-1 — `--web-url` for groups.** Confirm at implementation time whether `WebUrls` has or
  should gain a `group(group_id)` method (analogue of `WebUrls.post`). If the admin group deep-link
  pattern is known, add it; otherwise omit `--web-url` from `groups list` and note it in the spec.

## 6. Out of scope

- Write/manage groups (create, edit, delete, add/remove members) — deferred to the write line.
- Community hashtag write (create, delete) — deferred.
- Non-admin hashtag surface (post hashtags) — separate backlog item.
