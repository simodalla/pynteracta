# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## STOP — Workflow obbligatorio prima di ogni modifica

> **Non toccare alcun file finché non sei sul branch corretto.**

1. Crea e fai checkout del branch:
   - feature: `git checkout -b feature_<short_name>`
   - milestone: `git checkout -b m<n>_<short_name>`
   - bugfix: `git checkout -b bugfix_<short_name>`
2. Verifica: `git branch --show-current` — non deve essere `main`.
3. Solo allora modifica file o crea commit.

## What This Project Is

`pynteracta` is an unofficial Python 3.12+ library and CLI client for the Interacta™ REST API (`external_v2`). The library is synchronous-only (async deferred to v0.3). Current scope: service-account and Google OAuth2 auth, JWT lifecycle + caching, read-only access to auth/identity, users, posts, communities, and catalogs. Optional extras: `yaml` and `parquet` for `--export` CLI support.

La fonte di verità sui requisiti è [`specs/prd.md`](specs/prd.md).

## Regole non negoziabili

Vincoli che nessuna spec può violare. Le violazioni note stanno nella linea di partenza
(`specs/00-partenza/partenza.md`, id `P-<mm>`).

- **Token e segreti mai nei log.** Il transport redige `Authorization`, i JWT e i campi
  `token|password|secret|privatekey|assertion|jwt` dei body prima che richieste e risposte
  raggiungano log, audit log e hook; nessuna credenziale compare in log applicativi, audit log o
  messaggi di eccezione. (Da "Architecture > `transport.py`" e dalla v0.9.3.)
- **Cache del token con permessi stretti.** Su POSIX il file è `0o600` e la cartella `0o700`, e la
  cache si rifiuta di leggere se i permessi sono più larghi; la chiave di cache è per tenant; su
  Windows avviso una tantum e raccomandazione di `token_cache = "memory"`. (Da "Token cache
  security".)
- **Segreti fuori dal repository.** Nessuna credenziale nel codice né in file versionati; le chiavi
  di esempio sono finte e riconoscibili; `tests/integration/.secrets/`, `*.env` e `audit.log`
  restano in `.gitignore`. (Da "Before Committing".)
- **Soglie che non scendono.** La copertura minima (85 %), i controlli bloccanti e le regole di
  ruff e mypy non si allentano senza un ADR.
- **Dati personali fuori dai log, con l'eccezione dell'audit log.** Nomi, email e contenuti dei
  post non compaiono nei log applicativi. L'audit log opzionale (`audit_log`), che con
  `audit_log_bodies` registra i body delle risposte, è l'eccezione documentata, a carico di chi lo
  abilita.

## Architecture

### Module map (`src/pynteracta/`)

| Module | Role |
|---|---|
| `config.py` | `Profile` + `Config` pydantic models; `load_config()` / `resolve_profile()` with 4-level precedence: defaults < file < env < CLI overrides |
| `urls.py` | `build_api_base()` normalization + `WebUrls` helper for deep-link URLs |
| `exceptions.py` | Error hierarchy rooted at `InteractaError`; every exception carries `status_code`, `request_method`, `request_url`, `response_body`, `request_id` |
| `auth.py` | `ServiceAccountKey`, `TokenManager`, `FileTokenCache` / `MemoryTokenCache` |
| `transport.py` | `HttpTransport` wraps `httpx.Client`; injects `Authorization`, `User-Agent`, calls hooks, maps HTTP errors to exceptions; redaction of tokens: see "Regole non negoziabili" |
| `hooks.py` | `ClientHooks` Protocol + `RequestInfo` / `ResponseInfo` dataclasses — **no `httpx` types leak here** |
| `logging.py` | Named logger factory + `setup_default_logging()` opt-in helper; **never calls `structlog.configure()` at import time** |
| `models/generated/` | Auto-generated by `datamodel-code-generator`; **never hand-edit** |
| `models/facade/` | Hand-written ergonomic wrappers; use `ConfigDict(extra="ignore")` for forward-compat; `.raw` is a documented public escape hatch |
| `client.py` | `InteractaClient` top-level façade aggregating all resource APIs; supports service-account and Google OAuth2 auth |
| `api/_base.py` | `ResourceClient` base; `api/auth.py`, `api/users.py`, `api/posts.py`, `api/communities.py`, `api/catalogs.py` sub-clients |
| `api/_utils.py` | `build_paginated_body()` / `build_query_params()` shared helpers; `snake_to_camel()` conversion |
| `pagination.py` | `PageIterator` — lazy, stops on empty `nextPageToken` |
| `cli/` | Typer-based CLI; top-level entry point is the only caller of `setup_default_logging()` |

### Key design decisions

- **Hooks are httpx-free**: `RequestInfo`/`ResponseInfo` are plain dataclasses so the transport backend is swappable without breaking the public API.
- **Library never configures logging**: `structlog.configure()` is only called inside `setup_default_logging()`; importers of the library see no side effects.
- **Facade `.raw` is intentional**: composition exposes `.raw: generated.SomeDTO` as the documented escape hatch for fields not yet surfaced by the facade.
- **One method, one shape**: resource methods take explicit kwargs only; `*_raw(req: DTO)` variants exist for callers with pre-built DTOs.
- **Error mapping lives in `transport.py`**: `_map_error()` converts every HTTP status to the right `InteractaError` subclass.

### URL construction

API base: `{base_url}{base_path}/api/external/v{api_version}/`

`build_api_base` normalizes: strips whitespace, ensures scheme, strips trailing slashes, joins with single `/`. All four canonicalization vectors in `test_urls.py` must produce the same result.

### Configuration precedence

CLI flags > `PYNTERACTA_*` env vars > config file profile > built-in defaults.
Config file location: `platformdirs.user_config_dir("pynteracta") / "config.toml"` (override via `PYNTERACTA_CONFIG_FILE`).
`tomlkit` is used for any write operation to preserve user comments and formatting.

### Token cache security

See "Regole non negoziabili" (cache del token con permessi stretti).

## Testing Layout

```
tests/
├── unit/       # respx-mocked, no network — the default test run
├── contract/   # generated models vs pinned tests/fixtures/swagger.json
└── integration/  # opt-in (-m integration); requires .secrets/sa.json + env vars
```

Contract tests: regenerate models with `scripts/generate_models.py`, then run `pytest -m contract` to validate facade models still match the schema.

Integration test env vars (see `tests/integration/.env.example`): `PYNTERACTA_BASE_URL`, `PYNTERACTA_SERVICE_ACCOUNT_KEY`, `PYNTERACTA_TEST_COMMUNITY_ID`, `PYNTERACTA_TEST_USER_ID`, `PYNTERACTA_TEST_POST_ID`.

## Code Conventions

- All source files carry `# SPDX-License-Identifier: Apache-2.0` at the top.
- Line length: 100 (ruff). Ruff rule set: `E,F,W,I,B,UP,SIM,RUF,N,PT,PL`.
- `models/generated/` is excluded from ruff and mypy checks.
- Commit messages follow **Conventional Commits** (`feat:`, `fix:`, `perf:`, etc.), description in Italian (see "Lingua"). `BREAKING CHANGE:` footer triggers a major bump.
- `uv` is the package manager — use `uv add`, `uv sync`, `uv run`.
- Use `structlog.get_logger("pynteracta.<module>")` for all logging; never use `print`.
- Write automated tests for all code. Never delete test files.

## Before Committing

- `uv run ruff check .` and `uv run ruff format --check .` pass
- `uv run mypy src` passes (strict)
- `uv run pytest --cov --cov-fail-under=85` passes
- No commented-out code, debug prints, or hardcoded credentials (see "Regole non negoziabili")

## Metodo

Spec-driven development con il plugin `sddpa` del marketplace interno `ucrls`, abilitato in
`.claude/settings.json`. Ogni modifica di comportamento passa da una spec, con il suo branch, e segue
il ciclo:

`/sddpa:specifica <ambito>` → `/sddpa:piano <nn>` → `/sddpa:task <nn>` → `/sddpa:implementa [<nn>] <task>`
→ `/sddpa:verifica <nn>`, più `/sddpa:adr <titolo>` per le decisioni che cambiano il PRD o questo file.

Le regole del metodo (la spec dice cosa e il piano come, criteri `<nn>-C<mm>` mai riusati, test prima
del codice, approvazione che vale come commit, un commit per task) stanno nel plugin, in
`riferimenti/metodo.md`. Il progetto è in modalità `esistente`: si specifica solo ciò che si tocca,
e i controlli e la copertura non possono peggiorare rispetto alla linea di partenza. Ciò che è
proprio del progetto sta nella sezione "Configurazione SDD".

Rispetto a `WORKFLOW.md`: le fasi PLAN, BRANCH, IMPLEMENT, GATE e LOG sono svolte dal ciclo
`/sddpa:*` (la spec sostituisce `specs/vX.Y-<slug>.md`; `verifica` chiude la spec e aggiorna
ROADMAP e PROGRESS); la fase RELEASE (semantic-release, git-cliff, PyPI) resta quella del progetto.

## Configurazione SDD

Plugin: `sddpa` 0.3.0. Regole del metodo in `riferimenti/metodo.md` del plugin.

- Modalità: esistente
- Linea di partenza: `specs/00-partenza/partenza.md`
- PRD: `specs/prd.md`; requisiti: RF-xxx, RNF-xxx
- Spec: `specs/<nn>-<nome>/` (le spec per versione precedenti all'adozione sono in `specs/legacy/`, congelate)
- ADR: `specs/adr/`
- Branch principale: `main`
- Branch delle spec: `m<n>_<nome>`, dove `<n>` è il numero di milestone successivo all'ultimo usato in `PROGRESS.md` e nella tabella di `ROADMAP.md` (all'adozione l'ultimo è M26, quindi la spec 01 usa `m27_<nome>`)
- Deroghe al metodo: messaggi di commit: Conventional Commits (imposti da pre-commit e da semantic-release), descrizione in italiano
- Ambiente dei controlli: nessuno
- Controlli bloccanti: `uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy src`, `uv run pytest -m "not integration and not contract"`, `uv run pytest -m contract`
- Controlli a cricchetto: nessuno
- Copertura: `uv run pytest -m "not integration and not contract" --cov --cov-report=term-missing`; soglie: totale ≥ 85 % e mai sotto la linea di partenza; file toccati da una spec ≥ 85 %
- Marker dei criteri: `# criterio: <nn>-C<mm>` (commento sulla riga sopra il test)
- Controlli di verifica aggiuntivi: `uv run mkdocs build --strict`, `uv run pre-commit run --all-files`
- Voci aggiuntive della checklist:
  - endpoint e DTO del swagger pinnato toccati; serve rigenerare i modelli con `scripts/generate_models.py` (solo se il swagger cambia)?
  - esposizione in CLI tramite `render_output` (così `--output`, `--full`, `--fields`, `--web-url`, `--export` compongono) e snapshot `syrupy`?
  - pagine di `docs/` da aggiornare (`cli.md`, `api/*.md`, guide)? Il sito è pubblico e `mkdocs build --strict` lo verifica
  - riga ⏳ in `ROADMAP.md` all'apertura e sezione `M<n>` in `PROGRESS.md` (Done / Decisions / Follow-ups) alla verifica

## Lingua

Italiano per comunicazione, documenti, messaggi di commit e interfaccia, e per commenti e docstring
del codice nuovo o modificato. Nomi tecnici di classi, funzioni e variabili in inglese. Il codice e
la documentazione esistenti sono in inglese: restano come sono finché una modifica non li tocca.
