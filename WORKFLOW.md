# pynteracta — Project Evolution Workflow

> **Purpose.** This is the authoritative process document for how `pynteracta` is planned,
> versioned and documented from **v0.1.0 onward**. It captures the decisions taken on
> **2026-06-04** when the planning documents were restructured, and defines the workflow to follow
> for every future version. Keep it in sync with [`ROADMAP.md`](ROADMAP.md) and
> [`CLAUDE.md`](CLAUDE.md).

---

## 1. Why this exists (context)

The project shipped **everything** — foundation (M0–M7), Google OAuth2 (M8), communities/catalogs
(M9), audit logging (M10), `--full`/`--fields`/`--export` and bugfixes (M14) — in a single
**v0.1.0** tag (2026-06-04). Meanwhile the original plan still described a "v0.2 first release" and
listed already-implemented features as "out of scope", and the milestone log annotated itself with
version bumps (v0.2 → v0.5) that never happened.

The old model — **one immutable plan + one log** — broke because the project kept moving past the
plan and the real version (0.1.0) matched none of the numbers in the docs. The restructuring below
separates **history**, **forward plans**, **build log** and **changelog** into distinct artifacts
with a clear ownership.

## 2. Document model

| File | Role | Lifecycle |
|---|---|---|
| [`ROADMAP.md`](ROADMAP.md) | **Index.** Version table, versioning policy, full read-surface inventory, future backlog. | Living — edited in place. |
| [`specs/vX.Y-<slug>.md`](specs/) | **Per-version spec.** Endpoints, deliverables, acceptance criteria, open questions. Written *before* the work. | One per version; **frozen** once the version ships. |
| [`specs/v0.1-foundation.md`](specs/v0.1-foundation.md) | Frozen historical spec of the M0–M14 foundation that shipped as v0.1.0. | Frozen. |
| [`PROGRESS.md`](PROGRESS.md) | **Build log.** What was actually done, decisions beyond spec, follow-ups. Top "Version map" reconciles milestone↔tag numbering. | Append-only. |
| [`CHANGELOG.md`](CHANGELOG.md) | User-facing changelog. | Generated by `git-cliff` — never hand-edit. |
| [`CLAUDE.md`](CLAUDE.md) | Agent/contributor guidance, incl. the **STOP** branch rule and a pointer to this layout. | Living. |

**Rule of thumb:**
- Planning the future → `ROADMAP.md` + a new `specs/` file.
- Recording what happened → `PROGRESS.md`.
- Telling users what changed → let `git-cliff` generate `CHANGELOG.md`.
- Never edit a frozen spec; supersede it with a new one.

## 3. Versioning policy

- **Pre-1.0, lenient semver.** Every feature is a **minor** bump; even breaking changes bump the
  minor until 1.0. Configured in `python-semantic-release` (`allow_zero_version = true`,
  `major_on_zero = false`).
- **Cadence (decided 2026-06-04): one read-endpoint group per minor.** Next feature → **0.2.0**.
- **1.0 + PyPI** are deferred until the read surface is complete and the API has been stable for a
  while. Target audience today: **internal use / automations**.
- semantic-release computes the version from Conventional Commits; `tag_format = "v{version}"`.

## 4. The workflow (per version)

```
   ┌─ 1. PLAN ──────────────────────────────────────────────────────────────┐
   │  • Pick the next scope from ROADMAP.md (one read group per minor).      │
   │  • Create specs/vX.Y-<slug>.md  (copy the shape of an existing spec):   │
   │      endpoints + DTOs, deliverables, acceptance criteria, open questions│
   │  • Add a row to the ROADMAP version table; link the spec; mark ⏳.       │
   └────────────────────────────────────────────────────────────────────────┘
   ┌─ 2. BRANCH ────────────────────────────────────────────────────────────┐
   │  • git checkout -b feature_<slug>   (or m<n>_<slug> / bugfix_<slug>)    │
   │  • Verify: git branch --show-current  ≠ main   (see CLAUDE.md STOP)     │
   └────────────────────────────────────────────────────────────────────────┘
   ┌─ 3. IMPLEMENT ─────────────────────────────────────────────────────────┐
   │  • Follow the spec. Regenerate models only if the swagger changed.      │
   │  • Facade (extra="ignore", .raw) → api/ method (kwargs + *_raw) →        │
   │    CLI (via render_output) → tests (unit + contract + fixtures) → docs. │
   │  • Use Conventional Commits (feat: / fix: / docs: …).                   │
   └────────────────────────────────────────────────────────────────────────┘
   ┌─ 4. GATE ──────────────────────────────────────────────────────────────┐
   │  ruff check . · ruff format --check . · mypy src ·                      │
   │  pytest --cov --cov-fail-under=85                                       │
   └────────────────────────────────────────────────────────────────────────┘
   ┌─ 5. LOG ───────────────────────────────────────────────────────────────┐
   │  • Append an M<n> section to PROGRESS.md: Done / Decisions / Follow-ups.│
   │  • Resolve the spec's open questions; note the answers in PROGRESS.     │
   └────────────────────────────────────────────────────────────────────────┘
   ┌─ 6. RELEASE ───────────────────────────────────────────────────────────┐
   │  • Merge to main; semantic-release cuts the tag; git-cliff the CHANGELOG│
   │  • Mark the version ✅ in ROADMAP.md and FREEZE its spec header.         │
   └────────────────────────────────────────────────────────────────────────┘
```

### Adding a new endpoint (recipe)
Regenerate models (if swagger changed) → write/extend the façade model → add the resource method
(explicit kwargs + `*_raw` escape hatch) → add unit + contract tests + a JSON fixture → expose in
the CLI through `render_output` (so `--output`/`--full`/`--fields`/`--web-url`/`--export` compose)
→ update `docs/cli.md` and the relevant `docs/api/*.md`. (See also `CONTRIBUTING.md`.)

**Posts read completeness** — the seven `communication/posts/data/*` read endpoints not yet
covered (`post-detail-by-client-uid`, `post-capabilities`, `history-list`, `global-stream`,

hashtags → **0.6.0** admin manage edits. See [`ROADMAP.md`](ROADMAP.md) for the full inventory and
the deferred backlog (write operations, async client, Microsoft OAuth2 / username-password,
retry/backoff, PyPI 1.0).
